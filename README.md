# FinModel Lab · 财务模型实训平台

一个可以直接打开就用的财务建模练习网站。用真实财报数据搭模型，每一个空格都要自己写公式——
可以引用其他单元格、跨表引用、做加减乘除，和 Excel 一样。

## 怎么打开

**推荐**：在这个目录的上一级执行

```bash
python3 -m http.server 8777 --directory 财务模型学习网站
```

然后浏览器打开 `http://localhost:8777`。

也可以直接双击 `index.html` 打开——页面功能完全一样，
只是部分浏览器对 `file://` 下的本地存储有限制，进度保存可能不生效，所以建议用上面的方式。

没有构建步骤、没有 npm 依赖、不联网、不上传任何数据。

### 三种组织方式

- **学习路径**（`#/path`，推荐入口）：按**能力**递进排列，不按模型类型——
  读表 → 归因 → 预测 → 估值 → 交易，5 个阶段 23 步，每步都写了它在练什么、
  为什么排在这个位置。约 18 小时。
- **按模型分类**（`#/courses`）：10 类模型，每类下按 简单 / 中级 / 复杂 排列。
  适合已经有基础、想针对性补某一类的人。
- **全部模型**（`#/browse/all`）：按市场 / 难度 / 行业筛选。

### 关于难度标签

难度和工作量是**两个维度**，分开标注：

- 「简单 / 中级 / 复杂」= **概念难度**
- 「小 / 中 / 大 / 特大 · N 格」= **工作量**（待填单元格数）

两者不一定同向：腾讯 SOTP 只有 18 格但概念是中级；苹果利润表拆解有 49 格但概念很简单。
安排时间时看后者。

### 完整案例

标着「完整案例」的训练有 6–9 张工作表，起点是公司 10-K / 年报里**原封不动的三张报表**，
不是整理好的摘要。链路是：

```
历史利润表 · 历史资产负债表 · 历史现金流量表   （10-K 原文，小计合计要你自己加）
        ↓
     勾稽桥        ← 验证三表必须对上的线；解释注定对不上的差额是什么
        ↓
    驱动指标       ← 从历史反推利润率、周转天数、资本开支率
        ↓
    预测假设 → 预测利润表 → 预测资产负债表 → 预测现金流量表 → 现金回填 → 配平
```

目前有四个完整案例，其中两个是 A 股：

| 完整案例 | 类型 | 难度 | 表数 | 重点 |
|---|---|---|---|---|
| 苹果 · 从三张真实报表到三表联动预测模型 | 三表联动 | 复杂 | 9 | 勾稽桥 → 驱动提取 → 预测 → 配平为 0 |
| 苹果 · 从三张真实报表到 FCFF 估值 | DCF | 复杂 | 7 | 每个 DCF 输入项都指回报表的具体行号 |
| **贵州茅台 · A 股口径三表联动** | 三表联动 | 复杂 | 6 | 消费税、营业总收入 vs 营业收入、合同负债、财务公司科目 |
| **汇川技术 · 制造业口径三表联动** | 三表联动 | 复杂 | 6 | 营运资本（账期差 vs 资产基数）、研发加计扣除、结构性毛利率下滑 |

两个 A 股案例是刻意配对的：茅台教消费品口径（消费税、合同负债、财务公司科目），
汇川教制造业口径（营运资本、研发加计扣除、结构性毛利率下滑）。

茅台的数据来源需要说明：单一数据源的报表模板对茅台都不完整——新浪财经缺「拆出资金」
（茅台有集团财务公司），同花顺缺「买入返售金融资产」。两源合并后两年精确配平。
汇川没有财务公司，新浪的标准模板直接够用，资产负债表两年都能配平。
少数科目用「披露合计 − 已列示明细」倒挤，表内均已命名标注——这本身也是真实工作场景：
数据源和年报口径对不上时，正确做法是倒挤并命名，而不是硬凑。

第二个案例里的「报表到 FCFF 桥」会把 UFCF 与报表口径 FCF 对账（差约 118 亿美元，
来自利息税盾与股份支付），并演示资本结构用市值口径（2.9%）与账面口径（65%）的天壤之别。

## 主要功能

- **类 Excel 公式引擎**：`=B3-B6`、`=SUM(B3:B6)`、`='假设'!B14/365`、`=B27^(1/B26)-1`、`15%`、`$B$25`，
  支持 30 多个函数（SUM / AVERAGE / IF / NPV / IRR / PMT / SUMPRODUCT …），带循环引用检测。
- **鼠标点选引用**：编辑公式时点击其他单元格自动插入地址；按住拖过一片区域插入 `B3:D3` 区域引用。
- **跨表点选引用**：写公式写到一半可以直接切到别的工作表，点那边的单元格会插入 `'历史利润表'!C19`；
  编辑状态在切表时不丢，原表的标签会亮起圆点提示，按 Enter 提交后自动跳回。
- **拖拽填充**：选中格右下角有填充柄，往右/往下拖会复制公式并**自动平移相对引用**
  （`=B3-B6` → `=C3-C6`），`$` 锁定的部分不动。也支持 <kbd>Ctrl+D</kbd> / <kbd>Ctrl+R</kbd>。
- **复制粘贴**：站内 Ctrl+C/V 保留公式并平移；从 Excel 粘贴支持多行多列，以 `=` 开头的按公式写入。
- **键盘操作**：方向键导航、Shift+方向键扩选、F2/双击编辑、直接打字即编辑、Delete 清除选区。
- **自动判分**：数值容差 0.2%，答对标绿、答错标红；参考答案由引擎实时计算，不会和数据脱节。
- **进度保存**：每改一格自动写入 localStorage，记录最后修改时间与停留的单元格；
  首页显示"继续上次的进度"。支持导出 / 导入 JSON 备份。
- **公司与行业档案**：每家公司有案例背景（公司 + 行业）、财报特点、未来看法、风险点、关键财务数据；
  每个行业有该类公司财报特点的归纳总结与常见错误。
- **答错诊断**：检查之后点红色格子，侧栏会给出针对性诊断——符号写反、差 100 倍、算成倒数、
  忘了减 1、引用挪错一行/一列、校验行不为 0、硬写数字等。诊断由引擎从「你的值 vs 参考值」
  和「你的公式 vs 参考公式」自动推断，不需要逐格标注，新增模型自动获得。
- **导出 .xlsx**：训练页点「导出 Excel」下载真正的 Excel 文件（自建 ZIP + SheetML，无第三方库）。
  导出的是**公式不是结果**——跨表引用、`$` 锁定、SUM 区域全部保留，Excel 打开后自动重算；
  冻结首行首列、数字格式、分节标题底色都带上；附一张「说明」页含数据来源与要点。
  按住 <kbd>Shift</kbd> 点导出可生成含参考答案的版本。
- **深浅色主题**、响应式布局。

## 加自己的模型

在 `data/` 下新建一个文件，按 `_schema.js` 的构造函数写，然后在 `index.html` 里加一行 `<script>`。

坐标约定和 Excel 完全一致：**第 1 行是表头，A 列是科目名，数据从 B 列第 2 行开始**，
也就是 `rows[0]` 的第一个单元格地址是 `B2`。分节行 `SEC()` 和空行 `GAP()` 也各占一个行号。

```js
const { G, I, C, E, R, SEC, GAP } = window.S;

window.DB.addModel({
  id: 'my-model', market: 'secondary', level: 2,
  companyId: 'aapl', industryId: 'tech',
  title: '…', subtitle: '…', minutes: 30, tags: ['…'],
  intro: '…', objectives: ['…'], steps: [{ t: '…', d: '…' }],
  dataNote: '…', takeaways: ['…'],
  sheets: [{
    name: '利润表', unit: '百万美元',
    header: ['项目', 'FY2023', 'FY2024'],
    rows: [
      SEC('一、报表数据'),                                          // 第 2 行
      R('营业收入', [G(383285), G(391035)]),                        // 第 3 行
      R('营业成本', [G(214137), G(210352)]),                        // 第 4 行
      R('毛利润', [I('=B3-B4'), I('=C3-C4')], { style: 'tot' })     // 第 5 行
    ]
  }]
});
```

- `G(值)` 给定数据（只读）；`I('=公式')` 需要作答的格，参数是参考公式；
  `C('=公式')` 模型自带的只读计算格；`E()` 空格。
- 行选项：`fmt`（`pct1` / `pct2` / `num0`–`num4`）、`style`（`tot` 合计行）、`sub`、`note`。
- **参考答案不是硬编码的数字，而是公式**——引擎会用它实时算出标准答案，
  所以改了上游的原始数据，所有答案会自动跟着变，不会对不上。

### 自检

在浏览器控制台执行：

```js
validateAll()        // 校验全部模型：公式能否解析、有没有引用到空行/分节行、结果是否有限
dumpModel('byd-3s')  // 打印某个模型的全部参考答案数值，用来人工核对
```

`validateAll()` 能抓出行号写错这类问题（引用到分节行/空单元格会报错），
但抓不出"引用了一个存在但语义不对的行"——那种要靠 `dumpModel()` 看数值。

## 数据来源与免责声明

所有历史财务数据均整理自公司公开披露的年度报告、Form 10-K 及交易公告，
来源标注在每个模型的「数据说明」与每家公司档案的底部。

凡预测、假设、以及未公开披露的交易参数（如 LBO 的融资结构、协同效应、退出倍数），
均在表格内明确标注为「教学假设」。

本平台内容仅用于财务建模的技能训练，**不构成任何投资建议、估值结论或对相关公司与交易的评价**。
实际使用时请以公司披露的原始文件为准。
